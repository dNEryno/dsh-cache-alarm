# 缓存命中与速度

**只看本轮，不算累计、不算金额。**

- 每条助手回复的动作栏里只有一行四个值：`命中 · 首字 · 整轮 · tok/s`；命中率为整轮合计（该轮所有 assistant step 的计费桶求和），未命中、缓存读、缓存写、总计、输出等明细鼠标悬停查看。整轮耗时从本轮 `turnTimings.startTime` 到 `endTime`，不是单个 step 的解码时长。
- 输入框上方的「本轮」也只显示同样的四个值，流式输出中用 `tokenUsage` 投影差值实时预览，回复落定后立刻换成该条消息的真实用量；完整明细在悬停提示里。

命中率口径与官方一致：`cacheRead / (uncachedInput + cacheRead + cacheWrite)`，输出 token 不进分母。真实 TPS = `outputTokens / ((completedTime - firstTokenTime) / 1000)`，直接取这一条回复的 durable timing，不是官方那个平滑显示值。

## 颜色

| 颜色 | 含义 |
|---|---|
| 灰 | 这一轮还没有可用的 token 统计 |
| 绿 | 命中率 ≥ 90% |
| 黄 | 命中率 80%–89% |
| 红 | 命中率 < 80%，输入框横幅会提示换模型 |
| 红叉 ✕ | 请求失败 / 已中断 / 正在重试，显示原因而不是命中率 |

## 边界

- 没有缓存读字段的轮次显示 0% 而不是隐藏，方便看出冷启动/失效。
- 上一轮没有统计时，会回退到 turn-tail 的精确聚合；两者都没有才显示占位符。
- 首字延迟按 step 计算真实值：从 Session 原始事件流读取 `step/start` 到首个 text/reasoning/tool-call delta 的间隔，不再使用会话平均值；只有原始事件流与节点计时都没有首 token 时才显示 `—`。
- 插件不额外发请求、不注册工具、不改提示词，因此不会影响前缀缓存本身。
- 「极端低时发送前确认一次」尚未实现：当前只在横幅上给文字提示，不拦截发送。
